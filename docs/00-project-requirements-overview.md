# 项目总需求说明书

## 1. 项目名称

家政到家服务小程序平台。

项目名称、Logo、客服电话和公司介绍暂未确定，第一版开发时使用占位内容，后续统一替换。

## 2. 项目背景

本项目参考“金职到家”小程序的产品结构和业务逻辑，建设一个原创的家政服务平台。平台面向需要月嫂、保姆、育婴师、居家养老、保洁、钟点工、成长陪伴、家电清洗等服务的用户。

项目不是复制目标小程序的品牌、素材、代码或私有接口，而是实现同类业务能力。

## 3. 建设目标

第一版要完成一个可演示、可继续扩展的业务闭环：

```text
用户浏览服务人员
-> 用户发布需求或预约面试
-> 管理员审核需求并推荐阿姨
-> 用户查看推荐阿姨
-> 用户预约面试
-> 管理员后台跟进
-> 管理员上传合同并创建服务订单
-> 用户查看合同和订单
```

同时完成团购闭环：

```text
管理员发布团购商品
-> 用户单独购买或发起拼团
-> 商品详情展示正在拼团的人
-> 其他用户加入拼团
-> 满员后拼团成功
-> 用户获得待使用团购订单
```

## 4. 系统组成

- uni-app 微信小程序用户端。
- RuoYi-Vue-Plus Java 后端。
- RuoYi-Vue-Plus 配套 Vue 管理后台。
- MySQL 数据库。
- 阿里云 OSS 文件存储。

## 5. 用户角色

第一版只有两个角色：

- 普通用户：通过微信小程序使用平台。
- 管理员：通过管理后台维护全部业务。

第一版不做：

- 服务人员独立登录端。
- 多管理员权限角色。
- 在线聊天。
- 真实微信支付。
- 电子签章。

## 8. 核心业务规则

### 8.1 服务人员

- 服务人员由管理员后台录入。
- 服务人员可以上架、下架、设为推荐。
- 服务人员资料包含头像、姓名、城市、年龄、经验、学历、薪资、标签、证书、照片、工作经历、服务说明。

### 8.2 发布需求

- 用户发布需求后状态为“审核中”。
- 管理员可以审核通过或拒绝。
- 审核通过后，管理员可以给需求推荐一个或多个阿姨。
- 用户在需求详情中看到推荐阿姨列表。

### 8.3 预约面试

- 用户可以从阿姨详情页提交预约面试。
- 后台生成预约记录。
- 管理员线下联系用户并修改状态。
- 第一版不做在线聊天。

### 8.4 合同

- 第一版不做真实电子签。
- 合同由管理员后台上传文件。
- 用户端查看合同状态和合同文件。
- 合同状态为已签署、已终止。

### 8.5 团购

- 团购商品支持单独购买和拼团购买。
- 拼团商品详情展示正在拼团的人。
- 用户可以加入别人拼团。
- 满员后拼团成功。
- 第一版不接真实微信支付，使用模拟支付。
