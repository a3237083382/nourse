# 业务流程与状态设计

## 1. 找阿姨流程

```text
用户进入首页/找阿姨
-> 选择服务分类
-> 筛选服务人员
-> 查看阿姨详情
-> 收藏/分享/联系客服
-> 预约面试
-> 管理员后台跟进
-> 签署合同
-> 生成服务订单
-> 服务开始
-> 服务完成
```

## 2. 预约面试流程

用户端：

```text
阿姨详情
-> 点击预约面试
-> 填写或确认联系信息
-> 提交预约
-> 显示预约提交成功
```

后台端：

```text
预约记录为待处理
-> 管理员电话联系用户
-> 修改为已联系
-> 安排面试时间
-> 修改为已安排
-> 面试完成
-> 修改为已完成
```

预约状态：

- 待处理。
- 已联系。
- 已安排。
- 已完成。
- 已取消。

## 3. 发布需求流程

用户端：

```text
用户进入发布需求
-> 填写服务类型、周期、姓名、电话、地区、地址、薪资等
-> 提交需求
-> 状态为审核中
-> 查看需求详情
```

后台端：

```text
管理员查看需求
-> 审核通过或拒绝
-> 通过后选择推荐阿姨
-> 用户端需求详情展示推荐阿姨
-> 用户可查看推荐阿姨详情并预约面试
```

需求状态：

- 审核中。
- 已通过。
- 已拒绝。
- 已取消。

后台跟进状态：

- 待跟进。
- 已联系。
- 已匹配。
- 已签约。
- 已关闭。

## 4. 推荐阿姨流程

```text
需求审核通过
-> 管理员进入需求详情
-> 选择一个或多个服务人员
-> 填写推荐理由
-> 保存推荐
-> 用户端我的需求详情展示推荐列表
```

推荐状态：

- 已推荐。
- 用户已查看。
- 已预约面试。
- 已忽略。

## 5. 合同流程

第一版不做电子签，合同由后台维护。

```text
管理员创建合同
-> 绑定用户、服务人员、需求或服务订单
-> 上传合同 PDF/图片
-> 设置合同状态为已签署
-> 用户端我的合同查看
-> 如业务终止，管理员设置为已终止
```

合同状态：

- 已签署。
- 已终止。

## 6. 服务订单流程

服务订单来自两种情况：

- 用户通过预约面试后线下确认服务。
- 用户发布需求并选择推荐阿姨后线下确认服务。

流程：

```text
管理员创建服务订单
-> 待开始
-> 服务开始后改为进行中
-> 服务结束后改为已完成
-> 用户在小程序服务订单详情提交评价
-> 阿姨详情页展示用户评价
```

服务订单状态：

- 待开始。
- 进行中。
- 已完成。
- 已取消。

评价规则：

- 只有已完成的服务订单可以评价。
- 同一服务订单只能评价一次。
- 评价包含 1-5 分评分和文字内容。

## 7. 团购流程

### 7.1 单独购买

```text
用户进入团购详情
-> 点击单独购买
-> 选择规格和数量
-> 模拟支付
-> 生成团购订单
-> 状态为待使用
```

### 7.2 发起拼团

```text
用户进入团购详情
-> 点击拼团购买
-> 选择规格和数量
-> 模拟支付
-> 创建拼团
-> 团购订单状态为待分享
-> 拼团记录状态为拼团中
```

### 7.3 加入拼团

```text
用户在商品详情看到正在拼团的人
-> 点击去拼团
-> 模拟支付
-> 加入拼团
-> 满员后拼团成功
-> 参与订单状态改为待使用
```

拼团状态：

- 拼团中。
- 拼团成功。
- 拼团失败。
- 已取消。

团购订单状态：

- 待分享。
- 待使用。
- 已使用。
- 到期。
- 售后。

团购服务完成与评价：

```text
用户完成团购购买或拼团成功
-> 团购订单待使用
-> 管理员线下核销或标记已使用
-> 用户在团购订单详情提交评价
```

评价规则：

- 只有已使用的团购订单可以评价。
- 同一团购订单只能评价一次。
- 评价包含 1-5 分评分和文字内容。

## 8. 消息流程

触发消息的场景：

- 需求审核通过。
- 需求审核拒绝。
- 管理员推荐阿姨。
- 预约状态变化。
- 合同创建或终止。
- 团购拼团成功。
- 团购订单到期提醒。

第一版消息只做站内系统消息，不做短信和公众号模板消息。
