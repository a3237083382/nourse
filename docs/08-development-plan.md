# 开发计划与验收标准

## 0. 使用方式

本文档是后续开发的主任务清单。每完成一项任务，必须先完成验证，再把对应 `- [ ]` 改成 `- [x]`。

打勾规则：

- [ ] 开始任务前，先确认本阶段依赖是否已完成。
- [ ] 完成代码后，运行对应测试或手工验证。
- [ ] 验证通过后，更新本文档对应 TODO。
- [ ] 如果同一事项也出现在 `docs/00-project-requirements-overview.md`，同步打勾。
- [ ] 如果同一事项也出现在 `docs/superpowers/plans/2026-05-27-home-service-platform.md`，同步打勾。
- [ ] 最终回复里说明测试结果和已打勾的任务。

禁止事项：

- 没测试不打勾。
- 没完成不打勾。
- 验证失败不打勾。
- 不为省事跳过文档更新。
- 不做本文档之外的扩展功能，除非用户明确要求。
