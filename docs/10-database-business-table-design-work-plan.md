# 数据库业务表设计工作文档

## 1. 阶段目的

数据库业务表设计阶段用于把已确认的原型和业务流程落成稳定的数据结构。目标是让后续后台开发、小程序接口、订单状态流转都有清晰的数据来源。

这个阶段要避免临时建表和随手改字段。所有表、字段、状态、关联关系先在文档中确认，再写 SQL。

## 5. 设计规则

- 先复用 RuoYi-Vue-Plus 已有用户、权限、文件能力。
- 业务表只保存业务必要字段，不把页面展示临时字段硬塞进数据库。
- 状态字段统一使用文档中定义的枚举。
- 图片、证书、合同文件优先保存 `ossId` 和 URL 关联信息。
- 所有时间字段要有明确业务含义，如创建时间、审核时间、预约时间、成团时间。
- 第一版只考虑单管理员操作，不设计复杂权限表。
- 第一版支付为模拟支付，只保存模拟支付状态和支付时间。

## 6. SQL 文件规划

当前已创建并执行：

```text
sql/001_schema.sql
sql/002_seed_categories.sql
sql/003_user_staff_favorite.sql
```

说明：

- `sql/001_schema.sql` 创建 19 张核心业务表。
- `sql/002_seed_categories.sql` 初始化 8 个正式服务分类。
- `sql/003_user_staff_favorite.sql` 补充用户收藏服务人员表，支撑小程序收藏功能。
- 演示数据和正式基础数据分开，避免上线时混入测试数据。

## 7. 交付验收标准

- SQL 可以在本地 MySQL 执行成功。
- 核心业务表全部创建成功。
- 8 个服务分类初始化成功。
- 表字段能支撑已确认原型。
- 外键或逻辑关联关系清晰。
- 状态枚举与业务流程文档一致。
- 不需要手工修改数据库才能启动后续开发。
