# 后台业务模块开发工作文档

## 1. 阶段目的

后台业务模块开发阶段用于让管理员可以维护小程序所需的全部业务数据。第一版后台是运营核心，服务人员、需求审核、推荐阿姨、合同、团购等数据都从后台录入和处理。

后台开发要以可用、清晰、可维护为目标，不做复杂装饰和多角色权限扩展。

## 3. 输出物

- 后台业务菜单。
- 后台列表页。
- 新增、编辑、详情、审核、状态操作弹窗或页面。
- Java 后端 Controller、Service、Mapper、Domain、VO、BO。
- 管理前端 API 封装和页面组件。
- 后台功能验证记录。

## 4. 开发顺序

1. 服务分类管理。
2. 服务人员管理。
3. 服务人员证书、照片、经历管理。
4. 需求管理和审核。
5. 推荐阿姨。
6. 预约面试管理。
7. 合同管理。
8. 服务订单管理。
9. 团购商品管理。
10. 拼团管理。
11. 团购订单管理。
12. 内容配置和系统消息管理。

## 5. 后台页面规则

- 列表页必须有必要筛选条件。
- 表单字段必须和数据库、接口字段一致。
- 状态操作要有确认提示。
- 删除操作要谨慎，优先使用禁用、下架、取消等业务状态。
- 图片和文件上传复用已有文件管理能力。
- 金额字段统一明确单位，数据库建议用分，页面显示元。
- 不做多管理员角色权限，沿用当前 admin 管理员。

## 6. 后端接口规则

- 后台接口遵循 RuoYi-Vue-Plus 现有返回结构。
- 分页接口使用框架分页格式。
- 新增和编辑要做参数校验。
- 关键状态流转要防止非法跳转。
- 文件上传不暴露 OSS 密钥给前端。
- 业务异常要返回清晰错误信息。

## 7. 交付验收标准

- 管理员能完成服务分类和服务人员维护。
- 管理员能审核需求并推荐阿姨。
- 管理员能处理预约面试状态。
- 管理员能上传合同并创建服务订单。
- 管理员能维护团购商品、查看拼团和订单。
- 后台录入的数据能被小程序接口读取。
- 列表、筛选、分页、新增、编辑、状态操作可用。
