# 后台业务模块开发工作文档

## 1. 阶段目的

后台业务模块开发阶段用于让管理员可以维护小程序所需的全部业务数据。第一版后台是运营核心，服务人员、需求审核、推荐阿姨、合同、团购等数据都从后台录入和处理。

后台开发以可用、清晰、可维护为目标，不做复杂装饰和多角色权限扩展。

- 后台列表页面。
- 新增、编辑、详情、审核、状态操作弹窗或页面。

## 4. 开发顺序

1. 服务分类管理。
2. 服务人员管理。
3. 服务人员证书、照片、经历管理。
4. 需求管理和审核。
5. 推荐阿姨。
6. 预约面试管理。
7. 合同管理。
8. 服务订单管理。
9. 团购商品管理。
10. 拼团管理。
11. 团购订单管理。
12. 内容配置和系统消息管理。

## 5. 后台页面规则

- 列表页必须有必要筛选条件。
- 表单字段必须和数据库、接口字段一致。
- 状态操作要有确认提示。
- 删除操作要谨慎，优先使用禁用、下架、取消等业务状态。
- 图片和文件上传复用已有文件管理能力。
- 金额字段统一明确单位，数据库建议用分，页面显示元。
- 不做多管理员角色权限，沿用当前 `admin` 管理员。

## 6. 后端接口规则

- 后台接口遵循 RuoYi-Vue-Plus 现有返回结构。
- 分页接口使用框架分页格式。
- 新增和编辑要做参数校验。
- 关键状态流转要防止非法跳转。
- 文件上传不暴露 OSS 密钥给前端。
- 业务异常要返回清晰错误信息。

## 8. 验证记录

已完成的后台服务分类和服务人员模块通过以下验证：

- 后端构建：`mvn -pl ruoyi-admin -am -DskipTests package`，结果通过。
- 管理后台构建：Vite development build，结果通过。
- 后台接口冒烟：服务分类新增/编辑/禁用，服务人员新增/编辑/上架/下架/推荐，结果通过。
- 小程序公开接口联动：后台可见服务人员能被 `GET /api/app/staff` 和 `GET /api/app/staff/{id}` 读取。
- 服务人员上传页面验证：`ruoyi-ui` Vite 构建通过，头像、证书、照片上传控件编译通过。
- 需求审核推荐接口冒烟：用户提交需求后为 `PENDING/TO_FOLLOW`，后台需求列表返回 `code = 200`，审核通过后用户端为 `APPROVED`，审核拒绝后用户端为 `REJECTED/CLOSED`，推荐阿姨后用户端跟进状态为 `MATCHED`。
- 双推荐排序验证：同一需求推荐 2 位服务人员，用户端推荐列表按 `sortNo = 1, 2` 返回。
- 后端构建：`mvn -pl ruoyi-admin -am -DskipTests clean package`，结果通过。
- 管理后台构建：`node node_modules/vite/bin/vite.js build --mode production`，结果通过。
- 预约面试接口冒烟：用户提交预约后为 `PENDING`，后台预约列表可见；后台依次修改为 `CONTACTED`、`ARRANGED`、`COMPLETED`、`CANCELED` 均返回成功，用户端详情同步状态；后台备注保存后用户端详情可见。
