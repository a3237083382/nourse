# 联调测试工作文档

## 1. 阶段目的

联调测试阶段用于确认后端、管理后台、小程序、数据库、OSS 的整体链路可用。这个阶段不只看页面是否能打开，还要验证真实业务流程、状态变化、数据落库、文件上传和前后端展示是否一致。

只有通过联调测试的任务，才能在计划文档中打勾。

## 2. 输入资料

- `docs/00-project-requirements-overview.md`
- `docs/03-business-flows.md`
- `docs/08-development-plan.md`
- 后台业务模块开发结果
- 小程序页面开发结果

## 3. 输出物

- 联调测试用例清单。
- 测试账号和测试数据说明。
- 问题清单。
- 修复验证记录。
- 最终验收记录。

## 4. 联调范围

- 管理后台登录。
- 服务分类维护。
- 服务人员维护。
- 图片、证书、合同文件上传到 OSS。
- 小程序首页展示。
- 找阿姨列表和详情展示。
- 发布需求。
- 后台审核需求。
- 后台推荐阿姨。
- 用户查看推荐阿姨。
- 预约面试。
- 后台处理预约。
- 合同上传和用户查看。
- 服务订单创建和用户查看。
- 团购商品发布。
- 单独购买模拟支付。
- 发起拼团。
- 加入拼团。
- 拼团满员成功。
- 团购订单查看。
- 系统消息生成和查看。

## 5. 测试规则

- 每条用例要有前置条件、操作步骤、预期结果。
- 测试失败要记录问题，不打勾。
- 修复后必须重新验证原失败用例。
- 不只看前端提示，要确认数据库或后台列表中的结果。
- 文件上传要确认 OSS 控制台能看到文件。
- 小程序真机测试前确认合法域名配置。
- 第一版不测试真实微信支付、电子签章、在线聊天、服务人员端。

## 6. 关键验收链路

### 6.1 找阿姨链路

```text
后台新增服务分类和服务人员
-> 小程序首页或找阿姨列表展示
-> 用户进入阿姨详情
-> 用户收藏或预约面试
```

### 6.2 需求推荐链路

```text
用户发布需求
-> 后台看到待审核需求
-> 后台审核通过
-> 后台推荐阿姨
-> 用户需求详情看到推荐阿姨
```

### 6.3 合同订单链路

```text
后台上传合同
-> 后台创建服务订单
-> 用户合同页看到合同
-> 用户订单页看到服务订单
```

### 6.4 团购拼团链路

```text
后台发布团购商品
-> 用户单独购买或发起拼团
-> 其他用户加入拼团
-> 满员后拼团成功
-> 用户看到待使用团购订单
```

## 7. 交付验收标准

- 后端、后台、小程序都能启动。
- 第一版核心流程全部通过。
- 所有上传文件能写入 OSS。
- 关键状态流转正确。
- 数据库记录和前端展示一致。
- 已完成 Todo 都有对应验证证据。
- 未完成事项有原因和后续计划。

## 8. 任务清单维护规则

本文件只记录联调测试说明和验收口径，不再维护独立 Todo。

联调、真机测试、问题清单和交付整理任务统一维护在 `docs/08-development-plan.md` 的阶段十二中。
