# 金职到家参考小程序对比测试报告

测试日期：2026-05-31

本报告只做功能结构、交互体验和视觉质量对标，不复制金职到家的品牌、素材、图片、文案、代码或私有接口。

## 1. 测试范围

### 1.1 参考小程序

测试环境：Windows 微信桌面端小程序窗口。

- 服务分类入口。
- 团购活动列表和团购详情。
- 阿姨列表和阿姨详情。
- 预约面试表单入口。

## 2. 参考小程序观察

### 2.1 首页

参考端首页是高密度业务聚合页，首屏包含：

- 顶部品牌标题。
- 横幅广告图。
- 签约动态滚动提示。
- 8 个服务分类入口：月嫂、保姆、育婴师、居家养老、保洁师、钟点工、成长陪伴师、家电清洗师。
- 团购活动区，带图片、价格、销量、倒计时。
- 阿姨推荐列表。
- 悬浮客服按钮。

优点：

- 用户一进来能看到业务很完整。
- 真实图片让家政服务可信度更高。
- 团购和阿姨列表都在首页曝光，转化入口明显。
- 签约动态能制造平台活跃感。

问题：

- 首页信息较满，长列表滚动较深。
- 底部中间 Tab 文案显示为“找阿姨”，实际打开的是“发布需求”，命名和行为不完全一致。

### 2.2 阿姨详情

参考端阿姨详情内容非常丰富：

- 头像和基本资料。
- 薪资、地区、年龄、经验、服务类型、学历。
- 证书展示。
- “重审查、严筛选”信任背书。
- 身份认证、技能认证、无犯罪认证、体检报告。
- 基本信息表格。
- 长篇自我介绍。
- 多段工作经历。
- 用户评价。
- 底部固定操作：收藏、分享、预约面试、联系客服。

可借鉴方向：

- 详情页必须承担“建立信任”的作用。
- 证书、体检、无犯罪、身份认证等信息要有统一展示区。
- 工作经历、服务能力、用户评价要比列表页更详细。

### 2.3 预约面试

参考端预约面试从阿姨详情底部弹出表单，字段包括：

- 需求类型。
- 省市区。
- 工作地址。
- 工作日期。
- 薪资。
- 面试时间。
- 面试形式。
- 工作内容。

优点：

- 从阿姨详情直接预约，路径短。
- 预约表单信息足够让后台线下跟进。

### 2.4 团购

参考端团购详情包含：

- 大图。
- 原价、优惠价、销量。
- 消费须知。
- 有效期。
- 服务保障。
- 适用面积。
- 底部客服、拼团购、单独购买按钮。

优点：

- 商品详情页有购买决策信息。
- 单买和拼团入口并列清晰。

### 2.5 我的页面

参考端我的页面入口完整：

- 团购订单：待分享、待使用、已使用、到期、售后。
- 服务订单：待开始、进行中、已完成、已转让。
- 我的需求：审核中、已通过、已拒绝、已取消。
- 我的邀约。
- 我的收藏。
- 我的推荐。
- 常见问题。
- 用户协议。
- 隐私政策。
- 联系客服。
- 关于我们。
- 退出登录。

优点：

- 状态分组清晰。
- 空状态文案统一。
- 订单、需求、邀约、推荐都能从我的页回溯。

## 3. 当前小程序观察

### 3.1 已经具备的内容

当前小程序已经完成了第一版的基础骨架和若干核心流程：

- 底部 5 个 Tab 已具备：首页、合同、找阿姨、消息、我的。
- 首页有轮播、服务分类、签约动态、团购推荐。
- 找阿姨列表支持搜索、分类和筛选入口。
- 阿姨详情有基础资料、服务说明、证书、照片、工作经历、收藏、分享、客服、预约面试。
- 发布需求表单已经能打开，字段覆盖需求标题、服务类型、联系人、电话、住家、薪资、城市、区域、详细地址、补充说明。
- 预约面试表单已经能打开，字段包括联系人、联系电话，并提示后台会线下联系。
- 我的页有发布需求、我的需求、我的收藏、我的推荐、我的邀约、团购订单、服务订单、FAQ、协议、隐私、客服、关于我们入口。
- 管理后台和后端前面已接过需求审核、推荐阿姨、预约面试、消息触发等主链路。

### 3.2 本轮发现的问题

P0 问题：

- 找阿姨和阿姨详情使用了测试图片 URL：`https://example.com/test/photo-yuesao-1.jpg`，微信开发者工具控制台报 404。
- 合同 Tab 仍是占位页，只显示“我的合同 / 后续展示已签署和已终止合同”，没有合同列表、状态 Tab、文件查看。
- 消息 Tab 当前显示“暂无系统消息”，没有拿到测试消息数据，需要确认测试数据、当前 openid 和消息接口是否一致。
- 团购推荐只在首页露出，没有完整团购列表、团购详情、单独购买、拼团购买、团购订单闭环。
- 服务订单入口可见，但服务订单列表和详情未形成可测闭环。

P1 问题：

- 阿姨详情信息量明显少于参考端，缺少认证背书、体检报告、无犯罪认证、用户评价、更多工作经历展示。
- 预约面试表单字段偏少，只能填写联系人和电话，缺少面试时间、面试形式、工作地点、工作内容等后台跟进所需信息。
- 首页视觉比之前干净，但与参考端相比缺少真实服务图片和业务氛围，可信度不足。
- 我的页入口已经齐全，但订单、邀约、推荐等列表大多还没有真实数据状态分组。
- 当前仍是 mock 登录和“游客模式”开发环境，真实微信手机号快捷登录尚未接入。

P2 问题：

- 首页服务分类图标用单字占位，质感不如真实图标。
- 找阿姨列表卡片布局已有改善，但头像占位过强，真实感不足。
- 底部 Tab 图标仍偏测试感，需要换成统一风格的图标。
- 协议、隐私、关于我们等内容入口需要确认页面内容是否正式化。

## 5. 建议整改优先级

### 5.1 第一优先级：补齐闭环

1. 修复测试图片 404，把服务人员头像、证书、照片改为本地可访问测试图或后端文件资源。
2. 补齐合同列表、合同详情、文件预览和已签署/已终止状态。
3. 补齐服务订单列表、详情和状态。
4. 补齐团购商品列表、详情、单独购买、模拟支付、发起拼团、加入拼团、团购订单。
5. 修正消息测试数据，让需求审核、推荐阿姨、合同创建等消息能在当前 mock 用户下显示。

### 5.2 第二优先级：提升核心转化页

1. 阿姨详情新增认证背书区：身份认证、技能认证、体检报告、无犯罪证明。
2. 阿姨详情新增评价区和更完整工作经历。
3. 预约面试表单补充面试时间、面试形式、工作地点、工作内容。
4. 首页增加更明显的“发布需求”入口，但保留项目文档要求的“找阿姨”底部 Tab。
5. 我的页各入口统一做状态 Tab 和空状态。

### 5.3 第三优先级：视觉统一

1. 替换单字分类图标和底部测试图标。
2. 统一粉色主色的使用比例，减少测试感。
3. 首页、列表、详情使用真实但原创的家政服务场景图。
4. 卡片间距、字号、按钮高度继续统一，避免部分区域显得像临时页面。

## 6. 下一步建议

建议按以下顺序推进：

1. 先修复图片 404 和消息数据不显示问题。
2. 完成合同和服务订单，因为它们是当前 Tab 和我的页里最明显的空洞。
3. 完成团购闭环，因为参考端团购是首页重点转化模块。
4. 加强阿姨详情和预约面试字段。
5. 再做一轮微信开发者工具预览测试，并把 `docs/08-development-plan.md` 中对应 TODO 按验证结果打勾。

## 7. 本轮结论

当前小程序已经进入“核心家政流程初步可用，但交易、合同、订单闭环未完成”的阶段。

和参考小程序相比，我们的优势是业务边界更清楚、底部导航更符合项目文档；短板是详情页信任感、团购交易闭环、合同/订单闭环和真实图片素材还不足。

第一版上线前，最少需要补齐合同、服务订单、团购、消息测试数据和图片资源，否则用户会在主导航和我的页频繁遇到占位页或空状态。
