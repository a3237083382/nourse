## 2. 发现并修复的问题

### ISSUE-001 服务订单状态约束不一致

现象：

- 管理后台服务订单页面使用 `WAIT_START / SERVING / COMPLETED / CANCELED`。
- 小程序服务订单页面也按 `SERVING / CANCELED` 展示和筛选。
- 数据库约束仍是 `WAIT_START / IN_PROGRESS / COMPLETED / TRANSFERRED`。
- 后台调用“已取消”时触发 MySQL `chk_service_order_status` 约束错误，接口返回 500。

修复：

- `ruoyi/ruoyi-admin/src/main/java/org/dromara/web/controller/admin/AdminServiceOrderController.java`
  - 新增服务订单状态白名单校验。
  - 创建、编辑、更新状态接口统一使用 `WAIT_START / SERVING / COMPLETED / CANCELED`。
  - 非法状态返回业务错误，避免数据库 500。
- `sql/001_schema.sql`
  - 修正 `chk_service_order_status` 建表约束。
- `sql/006_fix_service_order_status.sql`
  - 新增现有数据库迁移脚本。
- `docs/05-database-design.md`
  - 服务订单状态说明同步为当前版本实际状态。

验证结果：

- 已执行 `sql/006_fix_service_order_status.sql`。
- 后端重新打包并启动成功。
- 完整 E2E 重跑后服务订单 `WAIT_START -> SERVING -> COMPLETED -> CANCELED` 全部通过。

### ISSUE-002 历史测试消息存在问号乱码

现象：

- 小程序消息页曾出现历史测试数据里的 `????` 内容。
- 重新导入测试数据后，干净用户仍可能读到旧的乱码消息。

修复：

- `sql/004_e2e_test_data.sql`
  - 导入测试数据前先软删除 mock 用户下的旧测试消息和包含问号乱码的历史消息。
  - 重新写入需求审核、推荐阿姨、合同创建、拼团成功等中文消息。

验证结果：

- 重新导入 `sql/004_e2e_test_data.sql`。
- 小程序消息接口返回 5 条干净消息：需求审核通过、需求审核拒绝、推荐阿姨、合同创建、拼团测试消息。
